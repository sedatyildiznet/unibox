# Unibox Native Runtime

This branch replaces the WSL2/Synapse/PostgreSQL bootstrap with a dependency-free Windows runtime shipped with Unibox.

## Goal

The Windows user should install one `Unibox-Setup.exe` and launch the application. The application must not require WSL, Docker Desktop, Hyper-V, Python, PostgreSQL, `apt`, systemd, a separate Linux distribution, an administrator shell, or a Windows reboot.

## Runtime layout

```text
Unibox.exe (Tauri + React)
  |
  +-- native runtime supervisor (Rust)
  |     |
  |     +-- tuwunel.exe              local Matrix homeserver
  |     +-- mautrix-whatsapp.exe      connector child process
  |     +-- mautrix-telegram.exe      connector child process
  |     +-- additional proven native connectors
  |
  +-- %LOCALAPPDATA%/app.unibox.desktop/runtime-native/
        +-- matrix/                    Tuwunel RocksDB/state/media
        +-- appservices/               generated Matrix appservice YAML
        +-- connectors/<id>/           connector SQLite/config/session state
        +-- secrets.json               local-only generated bootstrap secrets
        +-- matrix-session.json        local Matrix access token/device
        +-- logs/
```

All services bind to loopback only. Matrix federation and public account registration are disabled.

## Matrix homeserver

Use Tuwunel instead of Synapse for the desktop runtime. Tuwunel is implemented in Rust and provides a local Matrix homeserver without PostgreSQL or Python.

Unibox starts Tuwunel as a hidden child process and writes a minimal config approximately equivalent to:

```toml
[global]
server_name = "unibox.local"
database_path = "C:/.../runtime-native/matrix"
address = ["127.0.0.1"]
port = 8008
allow_federation = false
allow_registration = false
appservice_dir = "C:/.../runtime-native/appservices"
registration_shared_secret = "<random per-install secret>"
```

The exact config is generated by the Rust runtime supervisor, not manually edited by the user.

## Local Matrix identity

On first launch Unibox generates a random local password and registration shared secret, creates the private local Matrix user using the Synapse-compatible shared-secret registration API supported by Tuwunel, logs in through the standard Matrix client API, and persists only the resulting local session under the application data directory.

No Unibox cloud identity is created.

## Connector storage

Native mautrix BridgeV2 connectors use SQLite instead of PostgreSQL:

```yaml
database:
  type: sqlite3-fk-wal
  uri: file:C:/.../connectors/<id>/bridge.db?_txlock=immediate
```

Each connector is supervised as a hidden Windows child process. There is no systemd dependency.

Appservice registration files are generated by the connector into Unibox's `appservices` directory. Unibox restarts the local Tuwunel process after an appservice registration changes.

## Connector policy

A connector is exposed in production only after its Windows binary passes CI and a local end-to-end smoke test. Linux-only and Python-only connectors are not shown as working Windows integrations.

Initial target set:

1. WhatsApp
2. Telegram

After the native runtime is proven, other Go/Rust mautrix connectors are added one by one. Google Chat's legacy Python connector is deferred until it can be packaged without requiring a user-installed Python runtime.

## Build pipeline

CI builds the Windows homeserver and supported connector executables first, then places them in the Tauri resource/sidecar bundle before NSIS packaging. Production users never compile these projects locally.

Expected release contents are packaged inside or alongside `Unibox-Setup.exe`; no `apt`, `pip`, `cargo`, `go build`, or package-manager operation is performed on the user's computer.

## Migration from the WSL prototype

The WSL implementation remains isolated from this branch until the native runtime passes build and end-to-end tests. It is not used by the new runtime.

Because the current WSL builds are development prototypes, automatic migration of their local Matrix database is not required for the first native development release. A stale `UniboxRuntime` WSL distribution must not be touched by the native application unless the user explicitly asks to remove old prototype data.

## Definition of done

The native Windows installer is ready only when all of the following pass on a clean Windows 10/11 VM:

- Install without WSL/Hyper-V enabled.
- Launch without a console window.
- No UAC request for runtime provisioning.
- No reboot requirement.
- Tuwunel starts on `127.0.0.1:8008`.
- Local Matrix user/session is provisioned automatically.
- WhatsApp connector installs/starts using local SQLite.
- Telegram connector installs/starts using local SQLite.
- QR/login flow is visible inside Unibox.
- Restarting Windows/Unibox restores sessions.
- Uninstall leaves or removes user data according to an explicit user choice.
- Installer and runtime logs expose actionable errors rather than raw process output.
